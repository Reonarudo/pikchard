# @pikchard/pikchr-corpus

Every Pikchr Script the pinned upstream check-in ships, committed rather than
unpacked at test time — [ADR 0011](../../docs/adr/0011-the-upstream-script-corpus-is-committed-not-rebuilt-at-test-time.md).

It is a *conformance* corpus: it exists to show that what upstream accepts, we
accept. `lang-pikchr` parses all of it and requires no error nodes;
`pikchr-wasm` renders the `tests/` and `examples/` subset against its goldens.
Breadth is the point, so the corpus only changes when the pin moves — and when
it does, the diff is the thing worth reading.

## What is in `corpus/`

| Directory | Count | Where it comes from |
| --- | --- | --- |
| `tests/` | 103 | upstream `tests/*.pikchr`, verbatim |
| `examples/` | 3 | upstream `examples/*.pikchr`, verbatim |
| `grammar/` | 4 | upstream `grammar/*.pikchr`, verbatim |
| `fuzzcases/` | 3 | upstream `fuzzcases/*.pikchr`, verbatim |
| `doc/` | 148 | the body of every `pikchr` fence under upstream `doc/` |

Doc fences are named `<stem>-<short content hash>.pikchr`. `userman.md` alone
holds 71 of them and the directory is regenerated by deleting it, so ordinal
names would turn one fence inserted upstream into a 70-file rename. A content
hash means a new fence adds exactly one file, and a name changes only when the
Script did.

That naming also folds nine Scripts `userman.md` shows twice over — once as
`pikchr source toggle indent`, once as `pikchr toggle indent` — back into one
file each, which is why `doc/` holds 148 files for 157 fences. They are listed
under `duplicateFences` in `corpus/manifest.json`.

## Refreshing it

```
npm run extract -w @pikchard/pikchr-corpus
```

Node and nothing else: no Emscripten, and no `tar` subprocess. It deletes
`corpus/` and rewrites it from `packages/pikchr-wasm/vendor/`, so on an
unchanged pin it leaves `git status` clean. Regenerating the `.svg` goldens is
a separate step that *does* need Emscripten — `npm run goldens -w
@pikchard/pikchr-wasm`.

`src/pin.test.ts` fails if `corpus/manifest.json` and
`packages/pikchr-wasm/vendor/pikchr.lock.json` disagree about the check-in, so
bumping the pin without re-extracting cannot pass.
