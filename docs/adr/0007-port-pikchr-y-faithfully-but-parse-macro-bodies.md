# Port `pikchr.y` faithfully, but parse Macro bodies instead of keeping them opaque

ADR 0002 makes one Lezer grammar the source of highlighting, Spans, Symbols, and later completion, hover and Lints, but leaves its shape open. Two spikes were built and measured against the 270 Scripts in the pinned upstream tarball (prototype branch `prototype/grammar`, Task #1051): a structure-preserving port of `pikchr.y` where every production is a node, and a highlighting-first grammar where a Statement is a flat run of attributes and operands. The flat grammar is half the tree and twice as fast, but its tree cannot say whether a Script is even valid — it accepts `circle wid wid wid at at` without complaint — so Lints, hover and completion would each have to re-derive the structure from tokens. The argument that supposedly justified that price did not survive the spike: Lezer's own error recovery keeps highlighting stable on half-typed input in *both* grammars, so the faithful port colours a broken Script exactly as well and additionally marks the bad span. `packages/lang-pikchr` therefore ports `pikchr.y` production for production, in upstream's vocabulary, with one exception: `define m { … }` is parsed as a nested statement list rather than lexed as one opaque `CODEBLOCK` token, because an editor has to highlight what a compiler can ignore.

## Consequences

- The tree is roughly twice the size of the flat alternative and is rebuilt on every keystroke; Lezer's incremental parsing is what makes that affordable, so the grammar must stay incremental-friendly (no parse state that outlives a single `parse` call).
- Error nodes are a real signal rather than noise, so Lints (#1028) start from the tree instead of from a second pass, and `statementAt` and `symbols` read named nodes rather than re-deriving structure from tokens.
- Two external tokenizers carry what upstream's hand-written lexer does and Lezer's `@tokens` cannot: the one-word lookahead that decides whether a `.` is an edge, a coordinate, a property or a sublist label, and the raw balanced-parenthesis scan of a Macro argument list, which also enforces upstream's rule that the `(` follows the name with no space.
- Lemon's `%fallback ID EDGEPT` — which lets a compass word like `n` be a variable name wherever no edge is grammatical — has no Lezer equivalent and is expressed as a GLR ambiguity marker, letting the reading that cannot finish die.
- Parsing Macro bodies costs a `Parameter` token for `$1`…`$9` that is grammatical as a whole attribute, a whole position, and as the name in `define $1 { … }`, because a parameter can stand for any category at all. This is a deliberate divergence from upstream, which never has to decide what `$1` *is*.
- Upstream expands Macros in the lexer, so its parser never sees a call; the grammar invents a `MacroCall` production for the bare name and the argument-list forms. A Macro whose body expands to a *fragment* of a statement cannot be parsed by any static grammar and is accepted as a known gap.
- The grammar tracks a pinned upstream version. Keyword tables, the fourteen class names and the production set are all transcribed from one tarball, so an upstream sync means re-checking them — the same discipline ADR 0005 already imposes on the render path.
