# Markdown is the outer language of a Markdown Document, with Pikchr nested in its Fences

A `.md` Document holds prose with Pikchr Scripts scattered through it in Fences, and #1019 asks for one editor over the whole file. The shell prototype found the Fences with a line scanner (`prototype/shell`, `FENCE_OPEN`), which is the cheap answer and the one we rejected: it owns CommonMark's awkward cases forever — Fences indented inside lists, `~~~` nested in backticks, unclosed Fences at EOF — and re-scans on every keystroke. Instead the editor parses a Markdown Document with `@codemirror/lang-markdown` and nests `packages/lang-pikchr` into `pikchr` Fences through the `codeLanguages` hook, so a Script is a subtree of the Document's tree rather than a span some regex agreed with. The third option, showing only the Active Script and hiding the prose, contradicts #1019 and was not seriously in play.

## Consequences

- Scripts are read off the Markdown tree, incrementally, so CommonMark conformance is upstream's problem and not ours; #1042 becomes a tree query rather than a parser.
- A Script is always a **contiguous** slice of its Document and is never de-indented, even inside a list — Pikchr reads leading whitespace as whitespace, so an indented Script renders identically. Every Script→Document mapping is therefore `span.from + offset`: Render Error Spans, `data-pik` offsets, and later the Script↔Diagram map (#1029). Byte↔UTF-16 translation stays where it already is, at the `@pikchard/pikchr-wasm` seam.
- CodeMirror's `EditorState` is the single source of truth for the Document's text and its Scripts. The store holds a projection — Script count, Active Script index, Span and text — and never a second copy of the text.
- One predicate over the Fence's info string (first word `pikchr`, case-insensitive) drives both `codeLanguages` and the Script list, so what is highlighted and what is rendered can never disagree. The rest of the info string is ignored by us and preserved verbatim. Untagged Fences that happen to hold Pikchr are not detected; guessing wrong renders a shell snippet as a diagram.
- The nested parse hands the Pikchr parser *ranges* rather than one string, because `@lezer/markdown` strips a Fence's indentation for the inner parse. The Macro argument tokenizer reads one character backwards (`input.peek(-1)`) to enforce upstream's no-space-before-`(` rule, and both external tokenizers scan forward over raw text — all three can meet a range gap in an indented Fence. #1040 must test that case rather than assume it.
- A Document's language comes from its extension alone — `.md`/`.markdown` get Markdown, everything else including `.pikchr`, `.pik` and Untitled gets Pikchr directly. No content sniffing, no manual mode switch.
- `@codemirror/lang-markdown` and `@lezer/markdown` join the dependency tree of an app whose subject is not Markdown. That is the price of the decision, and it is paid once.
- Only the Active Script is ever rendered; switching Scripts re-renders. A per-Script Diagram cache would need Script identity across edits, which the Active Script rule deliberately avoids — if the budget ever demands one, key it by Script text.
